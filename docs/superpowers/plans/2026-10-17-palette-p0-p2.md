# Palette P0 to P2 and P4 Implementation Plan (blocks)

**Spec:** `docs/superpowers/specs/2026-10-17-palette-design.md`. **Branch:** `feat/palette`, cut from `dev`.
**Goal:** the bar launches apps (`hotkey, vsc, Enter`), has an action panel and mode chips, searches the web in Zen from
anywhere, and tags anything (`Ctrl+T`, then `#work`). Files behave exactly as before.

Built in blocks, one commit (or a few) per block, each leaves the repo green and demonstrable. The owner is shown the result
after blocks C, F, H and I and verifies by hand (no screenshots from the agent). Conventional commits, no attribution trailers,
no push without the owner's word. Spikes (marked S) run first, record what they measured in `docs/eval/`, and may change
the block after them.

## Global constraints

- Go from the repo root: `go vet ./...`, `go test ./...` clean, `gofmt` clean. Stdlib first; any new dependency is named
  in its block and justified. Frontend: `npm run check` and `npm test` clean. Engine untouched until P5 and P6.
- The hotkey path must not move: `cmd/panelbench -real` before and after each block that touches the page or the panel
  (baseline: 41 ms hotkey to focused input; limit 100 ms).
- Instant results come from memory: no disk, engine or network call between a keystroke and the rows.
- Shader and WebGL changes are checked on the real GPU, not only in a headless render (a software renderer accepted
  a program the real GPU refused to link).
- Docs in the same commit as the behaviour; `docs/STATUS.md` gets a row per phase.

## Block A: spikes (before any design is relied on)

**S1. Launching.** A throwaway Go program launches, by `ShellExecute`: a Start Menu `.lnk` (Code), Calculator and Settings
through `shell:AppsFolder\<AppUserModelID>`, and one app with the administrator flag. Record what works, how long until a
window exists, and what error an uninstalled target gives. Output: `docs/eval/2026-10-17-app-launching.md`.

**S2. Zen.** With Zen running and not running: `zen.exe <url>` (does it reuse the window and open a tab?), and
`zen.exe -search "<text>"` (does it use Zen's engine?). Output: `docs/eval/2026-10-17-zen-command-line.md`, and the choice
between URL template and `-search` for block H.

## Block B: ranking (`internal/rank`)

- `Match(query, title string) (score float64, ok bool)`: prefix, word start, acronym, subsequence with a gap penalty;
  case-insensitive; no dependency. Table tests: `vsc` to Visual Studio Code, `ppt` to PowerPoint, `chr` to Chrome over
  Character Map, no match for unrelated text, ties by shorter title.
- `Frecency`: a use count with exponential decay by age, `Score(uses []time.Time, now)`; tests with a fake clock.
- Commit: `feat(rank): fuzzy matching and frecency for the instant providers`.

## Block C: state and the palette model

- `internal/state`: `Load(path)`, `Save` (write a temp file, rename), a struct holding uses per item id, learned
  `prefix -> item` counts and tags. Tests: round trip, a corrupt file is moved aside and replaced, concurrent saves.
- `internal/palette`: `Item`, `Provider`, `Aggregator.Query(text, mode) []Section`, the mode chips (All, Apps, Files, Web,
  Tags) and prefix parsing, replacing `search.parseScope` (its tests move with it). Files stay on `internal/search` and the
  page merges the two answers.
- Frontend: `Tab` / `Shift+Tab` cycles the chip, `Esc` clears it before the text; the existing scope chip becomes the mode
  chip. `Ctrl+K` opens the action panel (a small list above the footer) with the actions of the selected kind: for files
  Open, Reveal, Copy path, Open in editor. Page logic tested in `flatten`-style unit tests.
- Commit(s): `feat(palette): modes, the action panel and the state file`.
- **Owner check:** files search as before; `Tab` cycles the chip; `Ctrl+K` lists actions and each works.

## Block D: finding apps (`internal/apps`)

- Scanner: Start Menu `.lnk` files (read target, arguments, display name) plus a background `Get-StartApps` for Store apps,
  merged by target; cached in `%LOCALAPPDATA%\AGI\apps.json`; refreshed at start, on Start Menu folder changes (reuse
  `internal/watcher`) and daily. The cache is loaded before the first keystroke.
- `Provider`: `Query` matches with `rank`, weights by frecency and learned prefixes, returns at most five on a strong match.
- Tests: scanner against a temp Start Menu tree (shortcuts, duplicates, hidden uninstallers such as "Uninstall X" are
  dropped), merge by target, provider ranking with a fake clock, a vanished target is dropped.
- **Measure:** refresh time; match time per keystroke over the real list (target under 2 ms p99); the list against
  `Get-StartApps` (nothing missing, nothing extra). Output: `docs/eval/2026-10-17-app-index.md`.
- Commit: `feat(apps): index the applications and match them as you type`.

## Block E: launching and icons

- `Launch(item)`: `ShellExecute` on the shortcut, `shell:AppsFolder\<id>` for Store apps (as S1 found), a missing target
  drops the entry and shows a one-line note; frecency and the learned prefix are recorded on success.
- `Ctrl+Enter` (show the folder) and run as administrator as secondary actions in the action panel.
- Icons: the shell's icon API into `%LOCALAPPDATA%\AGI\icons`, served at `/icon?id=...` next to `/thumb`, and drawn in the
  row tile. Tests: the cache key, the handler's refusal of ids that are not in the index.
- Commit: `feat(apps): launch from the bar, with icons`.

## Block F: apps in the bar

- The page shows the Apps section above Files, selected row first, `app:` prefix and the Apps chip; the key hints footer
  gains what applies to the selected kind. `Enter` launches and closes the panel without giving focus back (the launched
  program owns the keyboard, as `HideForLaunch` does for files).
- `cmd/panelbench -real` again: the hotkey path unchanged.
- Commit: `feat(launcher): applications in the bar`. **Owner check:** `hotkey, vsc, Enter`; try the apps used daily and
  report any that rank wrong, which become table cases.

## Block G: the browser (`internal/web`)

- Detect `zen.exe` through App Paths; `browser` and `search_url` (and `engine` if S2 favours `-search`) in `config.toml`,
  validated like the rest (a typo is an error). Open a URL or a search in the configured browser; no browser found is a
  clear note, never a silent fallback to Chrome.
- Quicklinks: `[[quicklink]] trigger, title, url` with `{q}`; the trigger word and a space activates it.
- Tests: URL building and escaping (spaces, `&`, unicode), template validation, trigger parsing.
- Commit: `feat(web): search and quicklinks in the configured browser`.

## Block H: web in the bar

- `Alt+Enter` from any mode, the Web chip and `?` prefix, the last row "Search the web for ...", quicklink rows.
- **Owner check:** type a question, `Alt+Enter`, Zen opens the search in a new tab of its running window; a quicklink works.
- Commit: `feat(launcher): search the web from the bar`.

## Block I: tags

- `internal/state` gains `tag -> item ids` (an id is a file path, an app id or a URL); `Tag(id, tag)`, `Untag`, `Tagged(tag)`,
  `TagsOf(id)`, tag names normalised (lower case, no spaces). Tests: add, remove, duplicates, normalisation, persistence.
- The bar: `Ctrl+T` on the selected row opens a one-line tag entry (existing tags complete as you type), Enter applies;
  `#work` lists everything tagged work (every kind, most used first), `#work budget` keeps the file results whose path is
  tagged or inside a tagged folder; a row shows its tags as small chips; the action panel gains Add tag and Remove tag.
- Commit: `feat(tags): tag files, folders, apps and links, and list them with #tag`. **Owner check:** tag a file and an app
  with `work`; `#work` lists both; remove one.

## Block J: close-out

- `docs/STATUS.md` rows for P0 to P2 and P4, `DESIGN.md` (mode chip, action panel, app rows, web row, tag chips), `docs/api.md` untouched,
  the config keys documented where the config is (`README` or `STATUS`), an ADR for any choice the spikes decided.
- Gates (Go, frontend, engine), `panelbench` numbers recorded, then a PR `feat/palette` into `dev` for the owner to merge.
