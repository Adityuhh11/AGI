# macOS M3: the engine side

Spec: `docs/superpowers/specs/2026-10-29-macos-design.md` (5.6, 5.9, section 8). Branch `feat/macos-m3`, from `dev` after M0 to M2 were merged.

1. **Folder watching** (`watcher/watch_darwin.go`, `.m`, `.h`): one FSEvents stream over all folders, file-level events, 0.5 s latency, delivered on a queue of its own (no run loop). Events are matched to the root
   by its resolved path and reported under the name it was given; a "events were merged or lost" flag pokes the whole root. The debouncer and the filter are the shared ones.
   The Windows tests of the watcher became shared tests: the same six cases must hold on both systems. The M1 stopgap that refreshed the app list when the bar opened is gone: the application folders are watched now.
2. **Folder permission** (`settingsui/access_*.go`): a Mac asks the person before a program first reads Documents, Desktop, Downloads, the media folders, iCloud Drive or a removable volume.
   Reading one entry of a chosen folder is what makes it ask, so that is done when the folder is chosen (in the background, one folder at a time so the questions do not pile up). A folder the system refuses is shown as
   such in Settings and in the guide, with a button to the right page of System Settings. A folder that is not chosen is never read.
3. **The Mac pins, run for real** (`enginesetup/real_darwin_test.go`, `llm/real_darwin_test.go`, a step of the `launcher-macos` job): the real `uv` and llama.cpp downloads, the real Python environment from `uv.lock`, then `uv`, `python`
   and both `llama-server` builds are started. Only the two embedding models are stand-ins. Nothing of the Mac install had run before this.

Not here: giving the engine's children the folder permission (they inherit this program's identity: for the friend to confirm), and the Mac bundle (M4).
