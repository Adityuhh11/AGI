# Launcher v1 Implementation Plan (blocks)

**Spec:** `docs/superpowers/specs/2026-10-15-launcher-design.md`. **Evidence:** `docs/eval/2026-10-15-launcher-experiments.md`.
**Goal:** a hotkey opens a plain black search bar; typing searches the `Sample Data/` index through the Python sidecar;
file-level results show the matching chunks; Enter opens the file. Nothing else.

Built in blocks, one commit (or a few) per block, each block leaves the repo green and demonstrable. The owner is shown
the result at the end of blocks D and E (the first visible UI) and asked wherever a choice is theirs. Branch
`feat/launcher`. Conventional commits, no AI attribution trailers.

## Global constraints

- Python (blocks A): from `sidecar/`, gate before every commit: `uv run ruff check .`, `uv run ruff format --check .`,
  `uv run pyright`, `uv run pytest`, plus `uv run python -m agi_memory.eval` for anything that changes ranking.
- Go (blocks B onward): from the repo root, `gofmt -l .` empty, `go vet ./...`, `go test ./...` clean. Stdlib first; each
  dependency named in its block. Wails v3 pinned to `v3.0.0-beta.29`.
- Frontend: Svelte and TypeScript; `npm run check` clean.
- Never read, index, log or commit `.env*` or `Sample Data/`. Config and logs under `%APPDATA%\AGI` and `%LOCALAPPDATA%\AGI`.
- Documentation changes ship in the same commit as the behaviour.

## Block A: engine changes for the launcher (Python, `sidecar/`)

**A1. Files, not chunks.**
- `SearchHit` and `SearchHitOut` gain `source_id`.
- `search/files.py` (or inside `searcher.py`): `Searcher.search_files(query, files=10, per_file=3, filters=None) ->
  FileSearchResult(files: list[FileHit], confident: bool)`. It runs the existing chunk search with a pool of 60 chunks,
  groups by `(source_id, uri)` in rank order, the file's score is its best chunk's, `kind` is the best chunk's kind, each
  file keeps up to `per_file` chunks. `FileHit(source_id, uri, kind, score, chunks: list[SearchHit])`.
- Route `POST /search/files` `{query, k (files, 1-50, default 10), per_file (1-10, default 3), filters}` returning
  `{files: [{source_id, uri, kind, score, chunks: [hit...]}], confident}`; same validation and auth as `/search`.
- Eval: measure the golden set at file level (`search_files`) and adopt it as the gate if it is the user-visible view
  (expected: equal or better ranks because duplicate chunks of a file no longer occupy slots). Re-record the baseline only
  if numbers improve; report both.
- Tests: grouping, per_file cap, file score = best chunk, order, empty query, filters, `confident` passes through;
  API tests for `/search/files` (validation, auth matrix gains the route, fields).
- Commit: `feat(search): file-level results with their best chunks, source_id on hits`.

**A2. `GET /sources`.** `FlatStore.sources() -> list[SourceInfo(id, root, last_scan_ns, files, chunks)]`; route returns
them; tests (empty, after a sync, after delete); auth matrix. Commit: `feat(api): list indexed sources`.

**A3. Query priority over indexing.** Problem measured: a search during indexing p50 226 ms, max 1568 ms (the query waits
for the whole embedding call: up to 64 text chunks or a 4-image batch). Steps: (1) measure first with a script that indexes
Sample Data copies while timing searches over HTTP (the approach of the launcher experiments), and record the baseline. (2) `SerializedEmbedder`: split bulk calls into slices (8 texts, 1 image)
with the lock taken per slice, and a waiting-queries counter so slices wait while any query is queued; queries take the
lock as soon as the slice in flight ends. (3) Re-measure; keep only what helps. Goal: search p95 under 300 ms during a
job, indexing throughput within 15% of before. Tests: a probe embedder shows a query waits for at most one slice and
bulk calls still return identical vectors in order; existing serialized tests pass. Commit:
`perf(embedding): queries take priority over bulk embedding`.

**A4. Docs.** `docs/api.md` (`/search/files`, `/sources`, `source_id`), `docs/STATUS.md` (phase 7a). Commit with A3 or alone.

## Block B: Go project skeleton

`go.mod` at the repo root (`module agi`), Wails v3 pinned, the CLI installed (`go install .../wails3@v3.0.0-beta.29`),
a frontend created with the Wails Svelte-TS template, `cmd/agi/main.go` opening one window that shows the Svelte page.
`internal/config` (TOML with `pelletier/go-toml/v2`): defaults, load, save, source-id derivation, table tests. `.gitignore`
for `node_modules`, build output. Commit per piece. Detailed steps written when this block starts.

## Block C: sidecar client and supervisor

`internal/sidecar`: typed client for `docs/api.md` against `httptest`; supervisor (token, free port, `uv run` start, Job
Object with `KILL_ON_JOB_CLOSE`, health polling, restart backoff, state events) against a fake process; a real-process
test behind a build tag. The app starts the sidecar at launch and shows `warming up` until ready.

## Block D: the panel (hotkey, cloak, focus hand-back)

`internal/panel`: window options, global shortcut (config hotkey, taken-hotkey reporting), cloak/uncloak, previous-window
focus restore, monitor placement, Escape and click-outside hide, toggle on a second press. `cmd/panelbench` (Windows)
reproduces the spike's measurement and fails over 100 ms p95. **Show the owner the empty black bar here.**

## Block E: search and the results UI

`internal/search` (debounce-free service: cancel, stale token, grouping display model), Wails bindings, the Svelte view
(input, rows for code/text, pdf, image placeholders, "+N more" expansion, keys), `internal/files` (`Open`, `Reveal`).
Against the Sample Data index. **Show the owner the working search here.**

## Block F: indexing manager and tray

`internal/indexing` (submit roots, handle 409, progress, rescan), `internal/tray` (status line, Rescan now, Quit), index
the sample folder at first start, graceful quit stopping the sidecar.

## Block G: thumbnails

`internal/files` thumbnail handler (decode, resize, cache, path allow-list), image rows with thumbnails.

## Block H: close-out

Docs (`ARCHITECTURE.md`, `STATUS.md`, a launcher section in `docs/README.md`), latency harness run recorded in
`docs/eval/`, manual acceptance list from the spec, independent code review, merge and push on the owner's word.
