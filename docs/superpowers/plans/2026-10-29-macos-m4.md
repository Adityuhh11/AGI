# macOS M4: packaging

Spec: `docs/superpowers/specs/2026-10-29-macos-design.md` (section 6). Built on `feat/macos-m3`, on top of M3, so one pull request into `dev` (and the one open from `dev` into `main`) carries M0 to M4.

1. **The bundle** (`build/darwin/Info.plist`, `omni.icns`, `scripts/release-mac.sh`): `Omni.app/Contents/{MacOS/omni, Info.plist, Resources/omni.icns}`. The plist carries the bundle id
   `io.github.adityuhh11.omni`, the version (three numbers, whatever follows `X.Y.Z` is dropped for the bundle and kept in the program), macOS 13 as the minimum, `LSUIElement` (no Dock icon at start;
   the guide and Settings take one while open), and the usage strings macOS shows when it asks for a folder. The icon is the pictures inside `omni.ico` packed as `.icns` by `scripts/make-icns.py`
   (no `iconutil`, no second source of art).
2. **Signing**: `codesign --force --deep --sign - --identifier io.github.adityuhh11.omni`, then `codesign --verify --deep --strict`. Ad hoc, as decided; the stable identity is M5.
3. **The zip**: `ditto -c -k --keepParent`, which keeps the signature, links and executable bits. Named `omni-X.Y.Z-macos-arm64.zip`.
4. **`install.sh`** (`scripts/install.sh`, published as a release file): checks Apple Silicon and macOS 13, reads the latest release from the GitHub API (the file list is JSON; the one tool a Mac
   has for it in the shell is JavaScript for Automation), downloads the zip, refuses it unless its SHA-256 equals the digest GitHub published, unpacks, verifies the signature, stops a running older
   Omni, swaps `Omni.app` into `~/Applications` by a rename, opens it. `OMNI_INSTALL_DIR`, `OMNI_API` and `OMNI_NO_OPEN` change the folder, the release and the opening; the test uses the last two and the second.
5. **The test** (`scripts/test-package-mac.sh`, run in `launcher-macos` on every pull request and in the Release workflow): the real `install.sh` against the real zip, served as a release file list made on the spot;
   a wrong checksum is refused and nothing is installed; installing over an install; the plist, icon, architecture and signature of the result; and the installed program started with `env -i` (the bare
   environment Finder gives a program) stays up and logs "omni starting".
6. **The release job** (`release.yml`, `macos`): after the Windows job (which checks the tag is on `main` and makes the draft), builds and tests the package, attests the zip and `install.sh`, uploads both to the draft and
   checks GitHub's digest of each is the one built. A hand run only uploads a workflow artifact.
7. **Docs**: `INSTALL-MAC.md`, the README's Mac block, `DISTRIBUTION.md` (macOS), `RELEASING.md`, `ARCHITECTURE.md` (build row), `STATUS.md`.

Not here: a quarantined-download test (a runner cannot be made to quarantine a file the way a browser does; for the friend), the stable signing identity and the Accessibility grant surviving an update (M5),
Developer ID and notarization (when the Apple account is paid for).
