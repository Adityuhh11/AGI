# macOS M0: make it compile, with the two systems visibly apart

Spec: `docs/superpowers/specs/2026-10-29-macos-design.md`. Branch: `feat/macos` (from `dev`). Windows behaviour must not change at any step.

## The rule every task follows

| File | Holds |
|---|---|
| `x.go` | Logic that is the same on both systems, and the declaration of what each system must provide (a comment names the functions). |
| `x_windows.go` | Windows only: Win32 calls, the registry, PowerShell, and pure-Go code that only makes sense for Windows (the Start Menu JSON). |
| `x_darwin.go` | macOS only: `open`, `pmset`, plist, and (from M1) cgo. |
| `x_windows_test.go` / `x_darwin_test.go` | Tests of the matching file. Tests of shared logic stay in `x_test.go` and run on both. |

No `x_other.go`: two supported systems, no third. A shared file never mentions a system's API; a system file never holds shared logic.

## The check after every task

- Windows: `go build ./... && go vet ./... && go test ./...` (nothing changes in behaviour).
- Mac, locally, for packages that do not import Wails: `GOOS=darwin GOARCH=arm64 CGO_ENABLED=0 go vet ./internal/<pkg>`. It type-checks the Mac files
  without a Mac. Packages that import Wails (`panel`, `tray`, `settingsui`, `cmd/omni`) and every cgo file can only be checked by the
  `launcher-macos` CI job (task 15).

## Tasks

Each is one commit (`refactor:` when only moving Windows code, `feat:` when Mac code appears).

1. **Data folders.** `config.DataDir()` and `config.LogDir()` in `paths_windows.go` / `paths_darwin.go`. Replace the `os.UserCacheDir()` call sites
   (`cmd/omni/main.go`, `remove.go`, `enginesetup/layout.go`, `llm/layout.go`) and always pass `OMNI_MEMORY_DIR` to the engine; drop the Python `LOCALAPPDATA` fallback.
2. **apps.** Shared: `Index`, `Catalog` (its `list` returns `[]App`), `icons.go` (HTTP middleware, warming, cache names). Windows: `parse_windows.go`
   (Start Menu JSON), `list_windows.go`, `launch_windows.go`, `focus_windows.go`, `icon_windows.go`. Mac: `list_darwin.go` (scan `.app`, `plutil`), `launch_darwin.go`
   (`open`, `open -R`), `icon_darwin.go` (M1 stub that says why). `CanRunAsAdministrator` constant per system; `StartMenuFolders` → `WatchedFolders`; `ShowInExplorer` → `RevealInFileManager`.
3. **system, power.** `system.go` has `Run`; each system declares its action table. Mac: `pmset`, `open -a`, `osascript`, `afplay`.
4. **web, files.** `web`: `appPath`/`shellOpen`/`Installed` per system. `files`: `shell_windows.go`/`shell_darwin.go` (`open`, `open -R`, VS Code, players); the shared player table and `findPlayer` logic move out of `players_windows.go`.
5. **autostart.** `autostart.go` (the API), `_windows.go` (Run key), `_darwin.go` (Wails `SMAppService`, state injected for tests).
6. **sidecar processes.** `exec_windows.go` unchanged; `exec_darwin.go` (process groups, `Kill`), `reaper_darwin.go` + the hidden `--reaper` subcommand (kill-on-launcher-exit through a closed pipe). `enginesetup.hide` per system.
7. **enginesetup, llm layout and pins.** `layout_windows.go`/`layout_darwin.go` (names), `pins_windows.go`/`pins_darwin.go`, `.tar.gz` unpack with modes, Mac device rule (Metal, no `--device`).
8. **watcher.** `watcher.go` declares `Watch`; Windows file unchanged; `watch_darwin.go` is the FSEvents stub for M3 that logs once and returns.
9. **clipboard.** `WindowsSource`/`NewPaster` stay Windows; `source_darwin.go`, `paste_darwin.go` (M2 stubs that say so); the elevated/secure-input messages per system.
10. **update.** `restart_windows.go` unchanged; `restart_darwin.go` (`kill(pid,0)`); the install step is not offered on the Mac (`Installable()`), the check still finds the release page.
11. **settingsui.** `keymenu_windows.go` stays; `keymenu_darwin.go` returns no filter; `knownfolder_darwin.go`.
12. **panel, tray.** `panel` seams per system (`win32_windows.go` unchanged, `native_darwin.go` M1 stub). `tray` template icon on Mac.
13. **cmd/omni.** The Windows-only options (`WndProcInterceptor`, `.exe` trimming, the log folder, the `--reaper` branch, the activation policy) move behind small per-system functions in `platform_windows.go` / `platform_darwin.go`.
14. **Frontend.** The platform comes from one Go service; `keycaps`, key labels and copy read it (M1 does the visible part; M0 only exposes the value).
15. **CI.** `launcher-macos` job in `ci.yml` (`macos-latest`): build, vet, test, page tests, bundle check. `scripts/build-mac.sh`.
16. **Docs.** `docs/ARCHITECTURE.md` "Platform code": the rule and the table of every pair; `AGENTS.md` pointer; `STATUS.md` phase M.

## Done when

`go build`, `go vet` and `go test` pass on Windows with identical behaviour, and the same three pass on `macos-latest` with the Mac seams answering honestly
("not available yet on macOS" for the ones M1 to M3 fill in).
