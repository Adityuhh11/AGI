# Pins in the first paint (2026-10-19)

Question (spec `2026-10-19-pins-clipboard-snippets-design.md`, phase P0): does opening the bar on a list of pinned
rows slow the hotkey to painted input? Limit for the feature: p50 not above 45 ms; the standing limit is p95 under
100 ms. Before: p50 36.2 ms, p95 42.4 ms (`2026-10-18-m2-release.md`).

## Method

`cmd/panelbench -real` opens the launcher's real page (`frontend/dist`) with a probe script and presses the hotkey 50 times
with another program holding the keyboard. The new `-pins N` flag registers the palette service over a catalog of N made-up
apps, all pinned, and the panel service the page resizes the window through, so the page opens on its "Pinned" list at the
height it left the window at. The made-up apps have no icons, so their rows show the glyph; the launcher's real apps
decode a small image each, which this does not measure (eight of them, cached, are small next to the 160 px thumbnails the
bar already decodes). Same laptop, same build (`443d6a4`), runs one after another, the desktop in use.

## Result (hotkey to painted, p50 / p95, 49 runs each)

| Run | No pins | Eight pinned rows |
|---|---|---|
| 1 | 31.7 / 42.5 ms | 34.6 / 44.4 ms (3 problems, one 152 ms run) |
| 2 | 34.6 / 39.3 ms | 33.3 / 37.6 ms |
| 3 | 33.0 / 41.8 ms | 34.6 / 38.4 ms |
| 4 | | 32.9 / 39.4 ms |

No difference beyond the noise between runs (about 2 ms at p50). The one bad run (3 problems, one slow outlier) is not
repeated in the three that followed and came while the desktop was being used; the others had no problems. Frame cadence
with the list on screen: 143 to 144 frames per second, longest gap 7 to 14 ms. **The fallback in the spec (pinned rows a
frame after the capsule) is not needed.**

## What the page does (checked in the real page, driven by key presses)

Opening shows a "Pinned" section with the rows in the order pinned and a pin mark on each. About six rows fit under the
panel's 640 DIP maximum height; the rest scroll with the arrow keys. `Down`, `Ctrl+P` unpinned the second row and the list
refreshed at once; `Esc` (nothing typed) closed the bar, and the next hotkey opened it on the same list, minus the
unpinned one, the first row selected, the ring in a new metal.
