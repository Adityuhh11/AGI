# The app index (2026-10-17)

Measured with `AGI_REAL_APPS=1 go test ./internal/apps -run RealStartMenu -v` on this machine's real Start Menu.

## What Windows lists, and what is kept

`Get-StartApps` returns 203 entries in 1.57 s (1.25 s when the machine is idle; 0.18 s of it is PowerShell starting). They are
not all applications:

| Kind of entry | Count | Kept? |
|---|---|---|
| Desktop programs with a plain AppUserModelID (`Microsoft.VisualStudioCode`, `Chrome`, `Excel`...) | 77 | yes |
| Store apps (`Package!App`) | 60 | yes |
| Executables by path (`{Program Files GUID}\7-Zip\7zFM.exe`) | 49 | yes |
| Admin consoles (`.msc`: Services, Task Scheduler...) | 3 | yes |
| Scripts (`.bat`: SQL Shell) | 1 | yes |
| Launcher links (`steam://rungameid/...`: a game) | 1 | yes |
| Websites (`https://...`) and `file://` links | 15 | no |
| Documentation by path (`.html`, `.chm`, `.pdf`), folders, a stray `.zip`, "Uninstall Node.js" | 12 | no |

176 are kept. All 27 dropped entries were reviewed by hand and none is something to launch. The rule is a keep-list
(what a Start Menu entry may point at), not a drop-list, so a new kind of junk is left out by default.

## Speed

- One query over 176 apps: **0.23 ms** (benchmark, 2052 allocations). Typing every prefix of every app name, 2535
  keystrokes: p99 1.5 to 3 ms in the coarse test loop, which is timer and garbage-collection noise, far under one frame. The
  target was 2 ms p99; the benchmark says it is met with a wide margin, and no optimisation was made.
- The list is served from `%LOCALAPPDATA%\AGI\apps.json` before the first keystroke and rebuilt in the background (at start
  when older than a day, when a Start Menu folder changes, and every day), so no keystroke waits for PowerShell.

## Does it find what you type?

| Typed | Top results (`?` is a weak match) |
|---|---|
| `vsc` | Visual Studio Code |
| `calc` | Calculator |
| `chr` | Google Chrome, Character Map?, Chess - Play & Learn? |
| `zen` | Zen, Zen Private Browsing |
| `exc` | Excel |
| `ppt` | PowerPoint? (weak, but first once letters on word starts count) |
| `word` | Word, Microsoft Whiteboard?, ... |
| `term` | Terminal |
| `note` | Notepad, OneNote, Sticky Notes |
| `code` | CodeMeter Command Prompt, CodeMeter Control Center, Visual Studio Code |

`code` shows the limit of name matching alone: two CodeMeter tools start with "code". Launching Visual Studio Code a few times,
or once after typing `code` (the learned prefix), puts it first; that is what frecency and learned prefixes are for.
