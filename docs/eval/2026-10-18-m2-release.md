## Not checked, and what to watch for in the friend's session

- **His machine.** An RTX 50-series card on the Vulkan build has not been run (the Vulkan path needs only the driver). If file search starts but is
  slow, the About page's "Copy diagnostics" and `omni.log` say which device the engine chose (`llama-server is ready on vulkan (...)` or `cpu`).
- **SmartScreen and antivirus.** The exe is unsigned, and the installer downloads `llama-server.exe` and `uv.exe` (pinned by SHA-256). A scanner that quarantines
  either shows up as an install that fails at "Getting llama.cpp" or "Getting the package tool".
- **A person with Python installed, a proxy, a different locale, a path with spaces or non-ASCII letters in the user name.** The install pins its own Python and
  keeps everything under `%LOCALAPPDATA%\Omni\engine`; none of these was tried.
- **Real folders.** Only `Sample Data` was indexed in the clean profile. The owner's 56k-chunk index was compared with the new embedder offline
  (`2026-10-18-llamacpp-embedder.md`), not re-indexed.
- **Cancelling a real download, and an interrupted network**: covered by tests with a local server, not tried against the real hosts.
- Questions that decide the next work are in the README's last section.
