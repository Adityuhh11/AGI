# M1: the launcher as a zip (2026-10-18)

Plan block C of `superpowers/plans/2026-10-18-packaging.md`. Built with `scripts/release.ps1`.

| Check | Result |
|---|---|
| Zip | `dist\omni-<date>-<commit>-windows-x64.zip`: `omni.exe` 12.7 MB and `README.txt`; 5.2 MB packed |
| Clean profile (unzipped to a new folder, `%APPDATA%` and `%LOCALAPPDATA%` empty) | starts; opens Settings by itself on the first run (a first start has no other window); creates `config.toml` with no folders, file search off, pace balanced; builds the app list (60 apps in 1.8 s with that empty profile, the per-user Start Menu was missing); no engine process is started; `omni.log` is written |
| Hotkey in the clean profile (`Alt+Shift+Space`) | opens the bar; typing shows the web row and the note "File search is off. Turn it on in Settings." |
| Settings, driven with real key presses on the owner's profile (hotkey, then `Ctrl+,`) | the window opens and the bar closes; General, Quicklinks (the owner's two), File search (the owner's seven folders) and About render; nothing was saved |
| Hotkey to painted input (`cmd/panelbench -real`, 49 runs) | input focused p50 33.2 ms, p95 39.0 ms; painted p50 33.8 ms, p95 39.8 ms (before this branch: 41 ms; limit 100 ms) |
| Settings window cost | the page of the window is a separate chunk (`import("./Settings.svelte")`), so the bar's page loads no settings code; the window itself opens in about 80 ms (`2026-10-18-wails-runtime.md`) |

Found and fixed on the way: with the engine off the footer of the bar said "Waiting for the search engine", and the page showed a
"Warming up" loader for any engine state it did not know. Both now treat `off` as nothing to wait for.

Not checked: a second physical machine (the friend's), a user whose hotkey is taken at the first start (the tray line and the
General page say so; tested with a fake registrar only), and SmartScreen (the exe is unsigned; the README says to click "Run anyway").
