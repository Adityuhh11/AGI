# Paste into another program, and the privacy formats (2026-10-19)

Spike for phase P1 of the pins, clipboard and snippets work: can Go put text on the clipboard,
give the keyboard back to the program the bar came from and type `Ctrl+V`, how long does it have to wait, and are the formats
password managers set honoured? The code is the product's (`internal/clipboard`); the tests are in
`real_windows_test.go` and run with `OMNI_REAL_CLIPBOARD=1` (they use the real clipboard, saving and restoring its text).

## Paste

Target: a window of another program (a PowerShell process with a Windows Forms text box, so it is a plain Win32 edit
control and nothing in a user's Notepad is touched). Each trial: the taskbar takes the keyboard, then the Paster sets the
clipboard, "releases the bar" (hands the keyboard to the target), waits until the target is the foreground window, waits
a settle time and sends `Ctrl+V` with `SendInput`. A trial counts when the pasted token is in the text box a second later.

| Settle time after the target is in front | Pastes that arrived |
|---|---|
| 0 ms | 8 of 8 |
| 10 ms | 8 of 8 |
| 40 ms (what the product waits) | 8 of 8 |

**Result:** the mechanics work, and a plain control accepts keys the moment it is the foreground window. The product keeps 40 ms
(`settle` in `paste.go`) as margin for programs that finish focusing a moment later (a browser's page, an editor). Ordering is
unit-tested without a screen (`paste_test.go`): text first, the keyboard handed back, a wait for the window, then the keys; a
window that never comes back gets no keys, and the text stays on the clipboard.

**Elevated windows.** Windows does not let a normal program send keys to an elevated one. The Paster asks first (`blockedByElevation`:
the target's program is elevated, or cannot even be opened to be asked, and this program is not elevated) and then copies
without closing the bar, saying why. **Not tested against a real elevated window**: that needs a UAC prompt, which a script
cannot answer. Still to be checked by hand: an elevated Notepad, Zen, Chrome, VS Code, Word and Windows Terminal (the test
list in the spec), where "paste" may need another key or a moment longer.

## Privacy formats (checked on the real clipboard)

A copy made with the text and one marker format, read back through `WindowsSource.Read`:

| Copy | Read as private |
|---|---|
| plain text | no |
| `ExcludeClipboardContentFromMonitorProcessing` present | yes |
| `CanIncludeInClipboardHistory` = 0 | yes |
| `CanIncludeInClipboardHistory` = 1 | no |
| `CanUploadToCloudClipboard` = 0 | yes |

The watcher's filters (private, a program on the ignore list, this program's own copies, only spaces, longer than 100,000
characters) are table tests in `watch_test.go`, with a fake clipboard.

## End to end, in the real app (clean profile)

The launcher built from this branch, a clean profile with the history switched on, a window of another program in
front. Four copies from another program (three ordinary, one marked with `ExcludeClipboardContentFromMonitorProcessing`),
the hotkey, `clip:`, then ` kubernetes`, then Enter.

| Step | Seen |
|---|---|
| History file after the copies | the three ordinary texts and the last one; the marked copy is not in it |
| `clip:` | the four, newest first, under a "Clipboard" chip, with "Enter paste, Ctrl+Enter copy" in the footer |
| `clip: kubernetes` | the one matching row |
| Enter | the text arrived in the other program's window; the bar closed; the entry moved to the newest place in the file |
| Settings > Clipboard | renders with the switch, the programs to leave out (the built-in ones listed), the count and Clear |
